# Products

- The catalogue is curated in-house. Only `PRODUCT_ADMIN` and `ADMIN` create and edit products. Norway has few enough groceries that this is feasible and gives better data than importing.
- A product has a barcode (EAN) or a PLU code (for loose goods), a name, optional brand, image, weight (grams) and volume (millilitres).
- Scanning an unknown barcode shows that the product is missing. Letting users propose it for admin review is a later feature.

Built: admins manage products at `/admin/products` (dashboard, create, edit). The profile page links there for admins. Rules enforced on save: name is required, at least one of barcode (8 to 14 digits) or PLU code (digits), weight and volume are optional whole numbers above 0, barcode and PLU code are unique.

Scanning: `/scan` opens the camera (ZXing, EAN-13/EAN-8/UPC-A/UPC-E), looks the barcode up and shows the product name and brand, or a "not found" message. If the camera is unavailable or denied, the user types the barcode instead. A known product shows a card with the name, brand, the cheapest current price and chain for the user's postal code ("fra 21,90 kr hos Rema 1000", the lowest of the latest report per chain), "Legg til på handlelisten" (or "På handlelisten" with "Se listen" and "Fjern"), "Rapporter pris" and "Se alle priser" (product page). "Rapporter pris" opens the price form in place with the price field focused, so scan, see price, add or report takes at most one tap. A price older than 30 days shows the staleness warning under the price. After a report, the price line switches to the new price if it is lower than the shown one (a higher new price for the same chain does not change it until the next scan). Without a postal code the card links to the profile, and with no reports it says so. An unknown barcode offers "Søk etter navn", which opens `/search`. Code: `src/features/scan`.

Search: `/search` has a text field that searches as you type: 200 ms after the last keystroke, from 2 letters, the URL becomes `?q=...` and the server renders the results, while the old results stay on screen (no blank flash) and the "Søk" button fades if the answer takes more than about 300 ms. A slow answer did not replace a newer one when tested with a delayed server. Typing replaces the history entry instead of adding one, so Back leaves the page, and clearing the field returns to the empty `/search`. Enter searches at once, even for one letter. Without JavaScript the form still works as a plain GET form. Typing below 2 letters sends nothing, so the old results stay until a new search runs.

Matching: it is case-insensitive (works for æ, ø, å) and typo tolerant, using Postgres `pg_trgm`. Results are ranked from best to worst: whole word in name or brand, start of a word, inside a word, description, fuzzy match (a misspelling such as "lettmlek" or "havergryn"). At most 50 results, each linking to `/products/[id]`, which shows a loading skeleton at once when tapped. Each row shows the cheapest current price and chain for the user's postal code ("fra 21,90 kr hos Rema 1000"), the lowest of the latest `PER_UNIT` report per chain, or nothing when there is none. The price comes from the same SQL query as the results (a lateral join on the final 50 rows), so it adds no round trip. Fuzzy matches (rank 4) are listed under a "Lignende treff" heading after the other results. The empty `/search` shows a hint ("Søk etter vare, for eksempel melk"); a list of most searched items would need a search log and is not built. When nothing matches, the page says so. Short terms are strict: under 3 letters (is, te, øl) match only whole words and word starts, and fuzzy matching needs 4 or more letters, because shorter words have too few trigrams to tell a typo from noise. Fuzzy results are ordered by how close they are. The search term is lowercased, punctuation (`, . - / ( )`) is treated as a space, and it is cut at 100 characters. A search with several words matches them as one phrase ("tine melk" does not find "Lettmelk" by Tine, except through the fuzzy match). Not handled: spelling without æ, ø, å is not reliably found ("smor" for "smør" only just reaches the fuzzy threshold, and "ol" for "øl" does not). Code: `src/features/search`, query `searchProducts` in `src/features/products/lib/queries.ts`.

Description: an optional free-text field on each product, edited in the admin form, used by search (for example "iskrem, dessert" on an ice cream product). It is not shown to regular users yet.

Unknown barcodes: a scan that finds no product is counted in `UnknownBarcodeScan` (barcode, count, first and last seen, `dismissedAt` for the admin dashboard), and the user sees "Takk, vi har notert den". Admin scans count too. To stop one person from inflating a count, a barcode counts at most once per user and Norwegian calendar day. For that, `UnknownBarcodeScanner` remembers a keyed hash (HMAC with `NEXTAUTH_SECRET`) of the user id per barcode and day, never the user id itself, and rows from earlier days are deleted on the next counted scan. Changing the secret only means a user can be counted once more that day. Recording is best effort: a failure is logged and the scan still shows its result, and without `NEXTAUTH_SECRET` nothing is recorded. The admin dashboard lists them (see below). Code: `src/features/products/lib/unknown-barcodes.ts`.

Admin dashboard: `/admin/products` has two tabs as plain links, with state in the URL (`tab`, `q`, `filter`, `page`), so reload, Back and sharing a view work. Only `PRODUCT_ADMIN` and `ADMIN` get it; the page checks the role itself, because the layout check runs in parallel and would not stop the data from being streamed to a `USER`.
- Produkter: one SQL query (`dashboard-queries.ts`) takes the latest report per product, chain and postal code over all postal codes (admins curate the whole catalogue) and returns per product the number of chains with a price ("3 av 9"), the cheapest per-unit price and chain, and the age of the newest report. The search field matches name, brand, barcode and PLU (a string of 8 or more digits is a barcode and matches exactly). The chips are single choice, with counts that ignore the search text: Alle, Uten priser (no report at all), Gamle priser (the newest report on the product is over 30 days old; products without reports are only under Uten priser) and Uten merke. 50 rows per page, sorted by name. From 1024 px it is a table where the whole row opens the edit page, below that a card list. A report older than 30 days is amber with a warning icon.
- Ukjente strekkoder: scans not dismissed and with no product that has the barcode (`NOT EXISTS`, so a barcode leaves the list by itself when a product is saved), most scanned first, at most 100 rows, and the tab badge shows the real count. "Opprett produkt" opens `/admin/products/new?barcode=...` with the barcode filled in (ignored if it is not 8 to 14 digits). "Ignorer" sets `dismissedAt` and the row shows "Ignorert" with "Angre", which clears it. The server actions are `dismissUnknownBarcode` and `restoreUnknownBarcode`, both behind `requireCatalogueEditor()`. The badge is not updated until the page is loaded again. A list of dismissed barcodes ("Vis ignorerte") is not built.

Scan to create: the product form (new and edit) has a "Skann" button next to the barcode field that opens the camera inline (the same `BarcodeScanner` as `/scan`) and fills the field. Without a camera it says "Kamera er ikke tilgjengelig. Skriv inn strekkoden." and the field stays usable. After a scan, `findProductWithBarcode` (behind `requireCatalogueEditor()`) checks the barcode, and a product that already has it is shown as "Finnes allerede: {name}" with a link to its edit page. The same link is shown if saving fails on a duplicate barcode. The rule "Strekkode eller PLU-kode (én av dem må fylles ut)" is shown above the two fields, and errors about the codes are shown under them. On `/scan`, `PRODUCT_ADMIN` and `ADMIN` get "Opprett produkt" (prefilled barcode) on an unknown barcode, and "Rediger produkt" on the public product page.

Not built: delete, image, proposals from users.

Code: `src/features/products`. Schema: `Product` in `prisma/schema.prisma`.
